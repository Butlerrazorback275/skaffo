# Phase 6 — Export واقعی ✅

آخرین فاز قبل از v1.0. خروجی گرفتن از «فقط نوشتن پوشه» به یک جریان کامل تبدیل شد.

---

## چی اضافه شد

### ۱. ZIP واقعی

`engine/app/services/export.py` آرشیو را در حافظه می‌سازد و یک‌جا می‌نویسد:

- همه‌چیز زیر **یک پوشهٔ ریشه** قرار می‌گیرد (استخراج، Downloads را به‌هم نمی‌ریزد)
- بیت اجرایی `run.sh` حفظ می‌شود
- تاریخ ثابت ⇒ آرشیو برای ورودی یکسان **بازتولیدپذیر** است
- `__pycache__`، `node_modules`، `.git`، `*.pyc`، `*.db` هرگز وارد نمی‌شوند
- فشرده‌سازی واقعی: ۶۷ KB → ۳۷ KB (**۴۴٪ کمتر**)

مسیر پیش‌فرض کنار پوشهٔ پروژه است، ولی می‌شود مسیر دلخواه هم داد.

### ۲. Dry run

دکمهٔ **Dry run** دقیقاً می‌گوید چه اتفاقی می‌افتد و **هیچ فایلی نمی‌نویسد**. برای وقتی که مطمئن نیستی تولید مجدد چه چیزی را عوض می‌کند.

### ۳. نمایش diff

کنار هر فایل تغییریافته آیکون مقایسه هست. کلیک کنی، diff یکپارچه با رنگ‌بندی باز می‌شود: خطوط اضافه‌شده سبز، حذف‌شده قرمز، و تعداد ناحیه‌های محافظت‌شده بالای پنجره.

فایل‌های خیلی بزرگ در ۶۰۰ خط بریده می‌شوند تا UI کند نشود.

### ۴. اسکریپت اجرا

`run.bat` و `run.sh` تولید می‌شوند: virtualenv می‌سازند، وابستگی‌های هر دو طرف را نصب می‌کنند، و هر دو سرور را بالا می‌آورند. کاربر نهایی فقط دوبار کلیک می‌کند.

با یک toggle می‌شود خاموشش کرد.

### ۵. گزارش بعد از export

کارت **Report** نشان می‌دهد: چند فایل نوشته/ادغام/رد شد، تفکیک فایل‌ها بر اساس ناحیه (backend / frontend / docker) با نوار پیشرفت، و پنج فایل بزرگ.

### ۶. باز کردن پوشه

دکمهٔ **Open Folder** فایل‌منیجر سیستم را روی خروجی باز می‌کند — Explorer در ویندوز، Finder در مک، `xdg-open` در لینوکس.

---

## 🐛 دو باگ واقعی (هر دو در تست UI پیدا شدند)

**۱. Dry run روی دیسک می‌نوشت.** شاخهٔ dry-run در تابع `generate()` اعمال نشده بود، پس `apply_plan` بی‌قید و شرط اجرا می‌شد. یعنی «پیش‌نمایش» عملاً فایل‌ها را می‌نوشت — دقیقاً برعکس کاری که باید می‌کرد.

**۲. اسکریپت‌های اجرا تولید می‌شدند ولی نوشته نمی‌شدند.** تابع `generate()` هنوز `run_all(ctx)` را مستقیم صدا می‌زد به‌جای `_files_for()`. در پیش‌نمایش و ZIP بودند، ولی روی دیسک نبودند — ناسازگاری بدی بین آنچه UI نشان می‌داد و آنچه واقعاً می‌نوشت.

هر دو با تست رگرسیون پوشش داده شدند:

```python
def test_dry_run_writes_nothing(tmp_path, files): ...
def test_run_scripts_survive_the_plan(tmp_path): ...
```

> نکته: هر دو باگ فقط با **تست انتها‌به‌انتها روی UI و بررسی دیسک** پیدا شدند. تست‌های واحد سبز بودند چون خودِ سرویس‌ها درست کار می‌کردند؛ مشکل در سیم‌کشی روتر بود.
